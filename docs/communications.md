# یکپارچه‌سازی ایمیل و چت

## یافته‌های ممیزی مخازن

- در `public/taxi-app/index.html` اتصال واقعی **Crisp** وجود داشت: اسکریپت `https://client.crisp.chat/l.js` با شناسهٔ عمومی سایت `ffafdfcf-e510-45d0-a026-4e964ad420ee` بارگذاری می‌شد و دکمهٔ پشتیبانی با فرمان `window.$crisp?.push(["do", "chat:open"])` گفتگو را باز می‌کرد.
- در مخزن قدیمی‌تر [`rahmaniho/karen-soft`](https://github.com/rahmaniho/karen-soft)، endpoint تماس در `app/api/contact/route.ts` از API رسمی Resend با `fetch` سمت‌سرور استفاده می‌کند. پیاده‌سازی از `RESEND_API_KEY`، `CONTACT_FROM` و `CONTACT_TO` می‌خواند، ورودی را اعتبارسنجی می‌کند و برای درخواست‌ها rate limit دارد.
- این پروژه با `output: "export"` ساخته می‌شود و خروجی فعلی GitHub Pages **استاتیک** است؛ بنابراین افزودن `app/api/contact/route.ts` به همین build کار نمی‌کند. برای فرم استاتیک Formspree یا یک API جداگانهٔ سروری لازم است.

## آنچه در این مخزن پیاده‌سازی شده

### چت Crisp

`components/shared/CrispChat.tsx` همان شناسه و فرمان‌های استخراج‌شده را به‌کار می‌برد، اما اسکریپت Crisp را تا زمانی که بازدیدکننده دکمهٔ «گفتگوی آنلاین» را نزند دریافت نمی‌کند. این کار بار اولیه و درخواست غیرضروری به سرویس ثالث را کم می‌کند. در صورت خطای بارگذاری، لینک تلگرام جایگزین نمایش داده می‌شود.

شناسه عمومی در صورت نیاز در زمان build قابل تغییر است:

```dotenv
NEXT_PUBLIC_CRISP_WEBSITE_ID=شناسه-عمومی-crisp
```

شناسهٔ فعلی داخل `lib/siteConfig.ts` به‌عنوان مقدار پیش‌فرض آمده است. این شناسه **کلید محرمانه نیست**.

### ارسال ایمیل

همهٔ فرم‌های تماس، درخواست محصول و سفارش چاپ از `components/shared/ContactForm.tsx` استفاده می‌کنند. ترتیب انتخاب مسیر ارسال:

1. اگر `NEXT_PUBLIC_CONTACT_API_URL` تنظیم شده باشد، payload استاندارد JSON به API امن شما فرستاده می‌شود؛ این گزینه بر Formspree اولویت دارد.
2. در غیر این صورت اگر `NEXT_PUBLIC_FORMSPREE_ID` تنظیم شده باشد، فرم با `FormData` به Formspree می‌رود.
3. اگر هیچ‌کدام تنظیم نشده باشد، دکمه متن فرم را در برنامهٔ ایمیل کاربر آماده می‌کند. رابط به‌صراحت می‌گوید که ارسال نهایی باید در برنامهٔ ایمیل تأیید شود؛ پیام را به‌اشتباه «ارسال‌شده» اعلام نمی‌کند.

تنظیم Formspree برای خروجی استاتیک:

```dotenv
NEXT_PUBLIC_FORMSPREE_ID=شناسه-فرم
```

مقدار باید هنگام build (از جمله در GitHub Actions/Vercel) حاضر باشد؛ شناسه را از پنل Formspree بگیرید. هیچ شناسهٔ واقعی در مخزن ثبت نشده است.

## راه‌اندازی ایمیل با Resend

نمونهٔ مستقل و قابل‌کپی در [`examples/resend-contact/route.ts`](../examples/resend-contact/route.ts) قرار دارد. برای استفاده:

1. آن را در یک پروژهٔ Next.js سمت‌سرور به `app/api/contact/route.ts` منتقل کنید؛ آن را داخل همین پروژهٔ استاتیک قرار ندهید مگر اینکه از خروجی استاتیک خارج شوید.
2. یک دامنهٔ فرستنده را در Resend تأیید کنید.
3. متغیرهای زیر را فقط در تنظیمات **سرور** مقصد قرار دهید:

```dotenv
RESEND_API_KEY=کلید-خصوصی-Resend
CONTACT_FROM=Karen Soft <noreply@دامنه-تاییدشده>
CONTACT_TO=info@karen-soft.ir
CONTACT_ALLOWED_ORIGIN=https://karen-soft.ir
```

4. اگر API روی دامنهٔ جداگانه قرار دارد، CORS فقط باید Origin دقیق سایت را مجاز کند؛ سپس URL عمومی API را در زمان build ست کنید:

```dotenv
NEXT_PUBLIC_CONTACT_API_URL=https://api.example.com/api/contact
```

`RESEND_API_KEY` هرگز نباید `NEXT_PUBLIC_` داشته باشد، وارد مرورگر شود یا در Git commit شود. نمونهٔ route اعتبارسنجی ورودی، ارسال متن ساده، timeout، بررسی Origin و محدودکنندهٔ best-effort دارد. محدودکنندهٔ درون‌حافظه‌ای در نمونه بین چند instance/serverless مشترک نیست؛ برای ترافیک واقعی، rate limit توزیع‌شده یا Vercel Firewall را هم فعال کنید.

## نکات حریم خصوصی

- فرم‌ها شمارهٔ تماس، ایمیل اختیاری و متن درخواست را فقط پس از ارسال به سرویس انتخاب‌شده می‌فرستند.
- Crisp یک سرویس ثالث است و ممکن است پس از کلیک کاربر داده‌های فنی مرورگر را پردازش کند؛ به همین دلیل اسکریپت آن پیش از تعامل بارگیری نمی‌شود.
- از ارسال اطلاعات محرمانهٔ پرونده، کارکنان یا پرداخت در دموهای عمومی خودداری کنید.
